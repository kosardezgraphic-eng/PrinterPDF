# Text overlays

Use **Insert → Add text** to create a text box on the active document (the document of the last page clicked or navigated to; otherwise the first highlighted or printable page). The page is brought into view and editing starts directly in the box. Select an existing text in move mode to show its formatting panel, irrespective of the current ribbon tab. Double-click it, or focus it and press Enter, to edit on the page. Click outside or press Ctrl/Cmd+Enter to commit; Escape discards the current text edit. Text entry uses a native textarea, including the browser's input-method and bidirectional editing support. A text edit is one workspace undo step; native text undo remains available while typing. The draft is committed before project save or PDF export.

Drag the selected box in move mode; use its eight handles to resize it. Ctrl/Cmd-drag makes an independent copy. Escape or pointer cancellation cancels a gesture. Geometry uses the page/sheet coordinate system and accounts for page and box rotation. Texts, style, position, scope, scripts, and spacing are stored in project JSON. Older text projects without the new optional fields retain the previous defaults.

## Targeting

A text can be attached to an **output sheet** or the visible box of a **document page**. Its percentage coordinates are relative to that target. A page text is drawn for each matching occurrence in an imposed layout, using its displayed crop box and occurrence transform; clipping follows the cell. Current and checked scopes capture the current sheet/page or checked page IDs when applied. The **Active document** scope captures the active page's document ID; **Selected documents** captures document IDs of highlighted pages (not the print checkboxes). Later pages belonging to those documents also match. Choosing a document scope attaches the text to pages. To switch back to an output sheet, choose the sheet target; the scope becomes the current sheet.

**Extend text coverage** adds to the base scope without replacing it. New text defaults to the active document. **Apply to all** is a toggle; turning it off returns to the original base scope. To include only some additional pages, enter their one-based workspace page numbers or ranges (for example `1, 3-5`, Persian and Arabic digits also work) and toggle **Apply to chosen**. When active, change the field and use **Update selection** to apply a new set. Turn the toggle off to return to the base scope. The selected pages are stored by page ID, so they follow those pages when reordered; this does not change which pages are checked for printing. Only pages included in a PDF export actually appear in its output. If the text is attached to an output sheet, the same controls use one-based output-side numbers instead; those are indices and can refer to different sheets if pagination changes. The base scope can still be changed explicitly in the base-scope controls, and disabling an extension returns to that current base scope. Coverage, chosen IDs/indices and their on/off state are undoable and saved in project JSON.

Even/odd/first/last page scope uses the original workspace page order, including unchecked pages; sheet scope uses output-side order. All occurrences of one text share its settings. A sheet-targeted checked scope matches a sheet if it contains a captured checked page. Current sheet uses the side index, which may refer to a different side if pagination changes. An unchecked active page can be edited in its preview without enabling it for printing; it appears in the exported PDF only when included in that export.

## Formatting and templates

The panel includes font, size, alignment, colors, opacity, rotation, line-height multiplier and extra word/letter spacing in points. Nonzero word and letter spacing require Canvas 2D support in the host browser; the panel warns when unavailable and PDF export fails rather than silently ignoring them. Select characters in the inline editor and use **x²** or **x₂** to toggle superscript or subscript. Edits preserve formatting outside the changed range and inserted characters inherit the preceding style (or the following style at the start). For complex bidirectional text, styling a portion can affect shaping at run boundaries.

Insert tokens using the panel or type them directly:

- `{page}`: one-based workspace page index for page targets, or output-side index for sheet targets; `{total}` is the corresponding total.
- `{sheet}`: one-based output-side index.
- `{file}` and `{docPage}`: document name and original source page number. For a sheet target these refer to its first populated cell, or an empty name and zero for an empty sheet.
- `{page+1000}`, `{page-1000}` or `{=page * 2}`: bounded integer arithmetic using `page`, decimal numbers, parentheses and `+ - * /`. Edit the expression directly in the text, or enter it in **Editable formula** and insert it. Persian and Arabic digits are accepted in formulas. The final result must be an integer in the range -999999999 to 999999999. No JavaScript, functions, property access or arbitrary code execution is supported. An invalid formula remains visible and prevents PDF export with an error.

The editor shows the literal token strings and unraised/unlowered text while typing; the resolved fields and script positioning appear after committing the edit. Long lines in the final Canvas rendering are fitted to the box width, while the textarea scrolls horizontally; therefore the editing view is not an exact WYSIWYG representation for long lines, scripts or resolved fields. Preview and PDF share the final Canvas renderer, including line and word/letter spacing where supported. Mixed-direction text and script-run boundaries can render differently from full rich-text layout; inspect the result before printing.

Vazirmatn, Shabnam and Sahel are bundled under their Open Font Licenses for offline use. Titr, Mitra, Nastaliq, Tahoma, Arial and Times New Roman are local system fonts; if missing, the browser uses a fallback. Text and optional background colors accept CSS color strings, including hex and RGBA. PDF text overlays are raster images at up to 200 dpi (not searchable/vector text) with a 4096-pixel per-side cap. Output can differ between operating systems when relying on fonts that are not bundled.

Page numbering is disabled for new workspaces; existing project settings are preserved. The existing numbering feature is distinct and can be enabled on the Insert tab. Legacy numbering and watermark output still have preview/PDF differences. Direct and batch printing are not connected to actual document submission.

Automated tests cover editable templates, safe formulas, reversible coverage and document scopes, inline editing, selection, resize, history, project restoration and PDF image generation. Actual Persian font appearance, complex bidirectional scripts, IME, touch, real printer output and high-page-count/frame-rate performance remain unverified. Font license texts are distributed in `public/licenses/` and included in production builds.

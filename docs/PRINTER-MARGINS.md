# Printer margins

The default margin mode follows the selected printer and paper. On Windows, the sidecar merges the queue's user/default print ticket with the requested media size and orientation, then asks the driver for its oriented media dimensions and imageable area. The four non-printable margins are calculated separately from the reported origin and extent (96 units per inch), converted to millimetres. Drivers that omit an imageable area, return invalid values, or report a different paper size are treated as unavailable; the last configured margins remain in place and are marked unverified. No fixed value such as 4.2 mm is presented as a measurement. Before any measurement the existing 10 mm layout value is an unverified fallback.

Queues whose names contain PDF, XPS, PrintStudio, Virtual or OneNote are **heuristically** classified as virtual and default to zero. Windows has no universally reliable virtual-printer flag in this implementation: a queue with an unusual name can be misclassified, or a physical queue with one of those words can be classified as virtual. Browser preview is a simulator, not access to hardware; its simulated virtual queue is labelled accordingly and simulated physical printers report unavailable.

Changing printer, paper, orientation or custom size triggers a new query, and stale results are discarded. Manual margin edits switch to custom mode and are preserved across queries. Reset uses the currently available printer result and is undoable; it is disabled while the result is unavailable or loading. Older project files without a margin mode are restored as custom, preserving their values. An explicit refresh can be requested by the store and the initial printer list refresh also queries again.

The sidecar requires Windows, a real driver and a published .NET executable. Driver-reported imageable areas are not a guarantee of the actual printer's mechanical accuracy; users should test their specific queue, paper and orientation. Tray/media profile changes are not yet translated into a native print ticket by the existing application. Native compilation, named-pipe operation and physical printing require Windows verification.
